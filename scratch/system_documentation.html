1. การกำหนดปัญหาและการวางแผน (3.1 การกำหนดปัญหาและการวางแผน)

1.1 การศึกษาและรวบรวมข้อมูล (3.1.1)

ผู้จัดทำโครงงานได้ดำเนินการศึกษาและรวบรวมข้อมูลเพื่อวิเคราะห์ปัญหาของระบบงานเดิม โดยใช้เครื่องมือและวิธีการดังต่อไปนี้:

  • วิธีสัมภาษณ์ (Interview): ผู้จัดทำได้สัมภาษณ์เจ้าหน้าที่ดูแลห้องปฏิบัติการคอมพิวเตอร์จำนวน 2 คน และนักศึกษาที่เข้าใช้บริการห้องปฏิบัติการจำนวน 3 คน เพื่อสอบถามเกี่ยวกับขั้นตอน ปัญหา และความยากลำบากในการดำเนินการยืม-คืนครุภัณฑ์ในรูปแบบเดิม
    *ปัญหาที่พบจากการสัมภาษณ์:* พบปัญหาว่าสมุดบันทึกข้อมูลมักสูญหายหรือค้นหาประวัติได้ยาก, นักศึกษาไม่ทราบจำนวนของคงเหลือที่ว่างให้ยืมจริงในคลัง ณ เวลานั้น, เจ้าหน้าที่ไม่สามารถควบคุมกำหนดส่งคืนได้สะดวกเพราะไม่มีระบบเตือน และเมื่อเกิดกรณีอุปกรณ์ชำรุดเสียหายมักไม่มีหลักฐานยืนยันสภาพอุปกรณ์ขณะส่งคืน
  • วิธีศึกษาเอกสารเดิม (Document Analysis): ผู้จัดทำได้ทำการรวบรวมและวิเคราะห์เอกสารที่เกี่ยวข้องในระบบงานเดิม เช่น สมุดจดบันทึกการยืม-คืนครุภัณฑ์ประจำห้องปฏิบัติการคอมพิวเตอร์, ไฟล์ตารางบันทึกรายชื่ออุปกรณ์ในโปรแกรม Microsoft Excel และใบคำร้องขอยืมอุปกรณ์แบบกระดาษ เพื่อทำความเข้าใจรูปแบบข้อมูลและนำมาใช้วิเคราะห์เพื่อออกแบบโครงสร้างระบบฐานข้อมูลใหม่ให้สอดคล้องกับการใช้งานจริง

1.2 การกำหนดขอบเขตระบบ (3.1.2)

ระบบจัดการยืม-คืนครุภัณฑ์ห้องปฏิบัติการคอมพิวเตอร์ ได้แบ่งสิทธิ์การทำงานของผู้ใช้งานออกเป็น 2 กลุ่มอย่างชัดเจน ดังนี้:

1.2.1 ผู้ใช้งานทั่วไป / นักศึกษาและอาจารย์ (User)

  • สามารถสมัครสมาชิก เข้าสู่ระบบ และแก้ไขข้อมูลส่วนตัวรวมถึงภาพโปรไฟล์ของตนเองได้
  • สามารถค้นหา คัดกรองข้อมูลครุภัณฑ์และวัสดุตามประเภท (ครุภัณฑ์ยืม-คืน หรือ วัสดุสิ้นเปลือง), หมวดหมู่ หรือสถานที่จัดเก็บ (อาคาร/ชั้น/เลขห้องปฏิบัติการ) ได้
  • สามารถยื่นขอยืมครุภัณฑ์ (ยืม-คืนแบบกำหนดวันมารับและส่งคืน) หรือยื่นขอเบิกวัสดุสิ้นเปลือง (ตัดสต็อกทันทีและไม่ต้องนำมาคืน) ได้
  • สามารถแจ้งส่งคืนครุภัณฑ์โดยการอัปโหลดไฟล์รูปถ่ายสภาพอุปกรณ์ขณะส่งคืน เพื่อใช้เป็นหลักฐานส่งให้ผู้ดูแลระบบตรวจสอบสภาพของก่อนรับคืน
  • สามารถตรวจสอบประวัติการทำรายการยืม-คืน และติดตามสถานะคำร้อง (รออนุมัติ / อนุมัติแล้ว / รอรับคืน / คืนแล้ว / ปฏิเสธ) ของตนเองได้
  • สามารถยื่นคำขอแจ้งซ่อมครุภัณฑ์เมื่อพบว่าอุปกรณ์ชำรุดเสียหาย พร้อมเขียนบันทึกอาการเบื้องต้นในระบบได้

1.2.2 ผู้ดูแลระบบ (Admin)

  • สามารถจัดการข้อมูลครุภัณฑ์และวัสดุ (เพิ่มคลังสินค้า, แก้ไขชื่อ, ปรับรหัสครุภัณฑ์, อัปเดตสถานะ, และอัปโหลดรูปภาพอุปกรณ์) ได้
  • สามารถจัดการข้อมูลสถานที่จัดเก็บครุภัณฑ์ (เพิ่ม/ลบ/แก้ไขข้อมูลรายชื่ออาคาร, ชั้นเรียน, และห้องปฏิบัติการต่าง ๆ) ได้
  • สามารถตรวจสอบรายละเอียดคำร้องและจัดการคำขอยืม-คืน (กดอนุมัติการยืม, ปฏิเสธคำขอพร้อมระบุเหตุผล, และกดอนุมัติการรับของคืนเข้าคลังหลังตรวจสอบความถูกต้องจากภาพถ่ายหลักฐานส่งคืน) ได้
  • สามารถส่งอีเมลแจ้งเตือนถึงผู้ยืมได้โดยตรง ทั้งการกดส่งเมลแจ้งเตือนด่วนรายคน หรือการกดรันคำสั่งตรวจสอบค้างส่งคืน (Daily Scheduler) เพื่อให้อีเมลแจ้งเตือนภัยด่วนสีแดงที่มีสัญลักษณ์ส่งไปยังอีเมลผู้ยืมที่ค้างส่งครุภัณฑ์เกินกำหนดโดยอัตมัติ
  • สามารถจัดการระบบคลังเก็บใบแจ้งซ่อมครุภัณฑ์ ตรวจสอบปัญหา และทำการอัปเดตสถานะการซ่อมบำรุงในระบบได้

1.3 เครื่องมือและเทคโนโลยีที่ใช้พัฒนา (3.4.1 เครื่องมือและเทคโนโลยีที่ใช้พัฒนา)

ผู้จัดทำโครงงานได้เลือกใช้เครื่องมือและเทคโนโลยีที่เหมาะสมในการพัฒนาระบบจัดการยืม-คืนครุภัณฑ์ ดังนี้:

  • 1.3.1 ภาษาโปรแกรมที่ใช้พัฒนา (3.4.1.1): ภาษา Python (เวอร์ชัน 3.10+) ร่วมกับเฟรมเวิร์ก Flask สำหรับการประมวลผลระบบหลังบ้าน (Back-end) และใช้ HTML5, CSS3, JavaScript (ES6) ในการเขียนดีไซน์โครงสร้าง จัดแต่งรูปแบบความสวยงาม และฟังก์ชันการคัดกรองข้อมูลฝั่งหน้าบ้าน (Front-end)
  • 1.3.2 ระบบจัดการฐานข้อมูล (3.4.1.2): ระบบจัดการฐานข้อมูลเชิงสัมพันธ์ PostgreSQL ผ่านคลาวด์เซอร์วิสของ Supabase Cloud Database เพื่อการเก็บรักษาความปลอดภัยของข้อมูลผู้ใช้งาน ข้อมูลพิกัดอุปกรณ์ และบันทึกคำร้องต่าง ๆ
  • 1.3.3 โปรแกรมที่ใช้พัฒนา (IDE / Tool) (3.4.1.3): Visual Studio Code (IDE สำหรับแก้ไขและเขียนซอร์สโค้ด), Git และ GitHub (ระบบควมคุมเวอร์ชันซอฟต์แวร์แบบแจกจ่าย), Vercel (คลาวด์โฮสติ้งในการปรับใช้งานจริง), และ Figma (สำหรับวางกรอบจำลองและดีไซน์อินเตอร์เฟสความสวยงามล่วงหน้า)

1.4 การติดตั้งและการนำไปใช้ (3.6 การติดตั้งและการนำไปใช้)

1.4.1 สภาพแวดล้อมและคุณสมบัติขั้นต่ำของระบบ (3.6.1)

  • 1.4.1.1 สำหรับเครื่องผู้ให้บริการ (Server Requirements) (3.6.1.1):
    • ระบบปฏิบัติการ: ใช้สภาพแวดล้อมระบบคลาวด์แบบ Serverless Node/Python Environment ของ Vercel (ฝั่งประมวลผลแอปพลิเคชัน) และระบบคลาวด์ Supabase (ฝั่งระบบจัดการฐานข้อมูล)
    • การประมวลผลและแพ็กเกจ: รองรับภาษา Python เวอร์ชัน 3.10+ พร้อมแพ็กเกจไลบรารี Flask, SQLAlchemy (ORM), pg8000 (โมดูลเชื่อต่อฐานข้อมูล PostgreSQL) และระบบเซิร์ฟเวอร์ SMTP (สำหรับส่งเมลเตือนคืนเกินกำหนด)
  • 1.4.1.2 สำหรับเครื่องผู้ใช้งาน (Client Requirements) (3.6.1.2):
    • อุปกรณ์หลัก: คอมพิวเตอร์ส่วนบุคคล (PC), แล็ปท็อป (Notebook), แท็บเล็ต (Tablet) หรือสมาร์ตโฟน (Smartphone)
    • เว็บเบราว์เซอร์: Google Chrome, Microsoft Edge, Mozilla Firefox หรือ Apple Safari (เวอร์ชันปัจจุบันที่อัปเดตล่าสุด)

1.4.2 การจัดทำคู่มือและฝึกอบรม (3.6.2)

ผู้จัดทำได้จัดทำเอกสารแนะนำขั้นตอนการใช้งานระบบยืม-คืนอย่างละเอียด เพื่อแบ่งการใช้งานให้ผู้ที่เกี่ยวข้องศึกษาก่อนปฏิบัติงานจริง ดังนี้:

  • คู่มือการใช้งานสำหรับผู้ใช้ทั่วไป (User Manual): อธิบายวิธีการลงทะเบียนเข้าใช้ระบบ, วิธีการค้นหาครุภัณฑ์ตามแผนผังอาคาร/ชั้น/ห้องปฏิบัติการ, ขั้นตอนการกดยื่นคำขอยืมครุภัณฑ์หรือเบิกวัสดุสิ้นเปลือง และขั้นตอนการแนบถ่ายรูปหลักฐานขณะส่งของคืนผู้ดูแลระบบ
  • คู่มือการใช้งานสำหรับผู้ดูแลระบบ (Admin Manual): อธิบายการเข้าบริหารจัดการสต็อกครุภัณฑ์ (เพิ่ม/ลด/แก้ไข), การจัดการแผนผังสถานที่เก็บ, การตรวจหลักฐานภาพถ่าย และการยืนยันรับของคืน ตลอดจนการกดรันคำสั่ง Daily Schedule ส่งเมลแจ้งเตือนถึงผู้ยืมค้างกำหนด

1.5 การบำรุงรักษาและการประเมินผล (3.7 การบำรุงรักษาและการประเมินผล)

1.5.1 การบำรุงรักษาและการสำรองข้อมูล (3.7.1)

  • การสำรองข้อมูลฐานข้อมูล (Database Backup Plan): กำหนดนโยบายความมั่นคงปลอดภัยในการสำรองข้อมูลเชิงสัมพันธ์ของระบบ (เช่น ข้อมูลบัญชีสมาชิก สต็อก และประวัติยืมคืน) โดยตั้งระบบอัตโนมัติบน Supabase Cloud ให้ทำการสำรองโครงสร้างข้อมูล (Database Snapshot & SQL Dump) ทุกวันอาทิตย์ เวลา 00.00 น. เพื่อรักษาระดับเสถียรภาพและป้องกันกรณีข้อมูลสูญหาย
  • การบำรุงรักษาประวัติระบบ (Log Maintenance & System Audit): กำหนดให้มีแผนการตรวจสอบสถิติการใช้งานและไฟล์บันทึกประวัติการส่งคำร้อง (Vercel Server Logs) ทุกสิ้นเดือน เพื่อลบไฟล์ประวัติขยะบนแคช ค้นหาจุดเกิดปัญหา (Errors) เพื่อปรับปรุงโครงสร้างเซิร์ฟเวอร์ให้อัตราความหน่วงต่ำที่สุดอย่างสม่ำเสมอ

1.5.2 การประเมินผลความพึงพอใจของระบบ (3.7.2)

  • กลุ่มตัวอย่างประเมิน: กลุ่มผู้ทดลองใช้งานระบบจัดการยืม-คืนจริง ได้แก่ นักเรียน/นักศึกษาสาขาคอมพิวเตอร์จำนวน 30 คน และผู้ดูแลระบบ/อาจารย์ประจำห้องปฏิบัติการคอมพิวเตอร์จำนวน 2 คน
  • เครื่องมือประเมินผล: ใช้แบบสอบถามวัดระดับความพึงพอใจ (Satisfaction Survey) ผ่านระบบออนไลน์ Google Forms โดยแบ่งหัวข้อการประเมินประสิทธิภาพออกเป็น 4 ด้านหลัก ได้แก่:
    (1) ด้านความสอดคล้องการทำงานตามความต้องการระบบ (Functional Requirements)
    (2) ด้านความง่ายต่อการเรียนรู้และเข้าใจในการใช้งาน (Usability & User-friendliness)
    (3) ด้านการออกแบบสไตล์ ความสวยงาม และการรองรับการแสดงผลโหมดมืด (User Interface Design)
    (4) ด้านความเร็ว ความเสถียร และอัตราการตอบสนองที่ไม่หน่วงค้าง (System Performance)
  • สถิติที่ใช้คิดคะแนน: ใช้ค่าเฉลี่ยเลขคณิต (Mean: \(ar{X}\)) และส่วนเบี่ยงเบนมาตรฐาน (Standard Deviation: \(S.D.\)) ในการคำนวณและแปลงระดับคะแนนความพึงพอใจออกเป็นเกณฑ์ 5 ระดับของ Likert Scale (พึงพอใจมากที่สุด - พึงพอใจน้อยที่สุด) เพื่อสรุปคุณภาพโครงงาน

2. แผนภาพบริบท (Context Diagram)

แผนภาพระดับบนสุด (DFD Level 0) แสดงขอบเขตการทำงานของระบบและการแลกเปลี่ยนกระแสข้อมูลระหว่างระบบจัดการครุภัณฑ์ห้องปฏิบัติการคอมพิวเตอร์กับหน่วยงานภายนอก (Entities) ได้แก่ ผู้ใช้ทั่วไป, ผู้ดูแลระบบ (Admin) และระบบส่งเมลเซิร์ฟเวอร์ (SMTP Server)

รูปที่ 3-2: แผนภาพบริบทของระบบจัดการยืม-คืนครุภัณฑ์ห้องปฏิบัติการคอมพิวเตอร์ (Context Diagram)

คำอธิบายรายละเอียดแผนภาพจากรูปที่ 3-2: แสดงแผนภาพบริบทของระบบจัดการยืม-คืนครุภัณฑ์ห้องปฏิบัติการคอมพิวเตอร์กับผู้ที่เกี่ยวข้องภายนอก ได้แก่ 'ผู้ใช้งานทั่วไป (นักศึกษา/อาจารย์)', 'ผู้ดูแลระบบ (Admin)' และ 'ระบบส่งอีเมล (SMTP Mail Server)' โดยระบบนี้ทำหน้าที่เป็นศูนย์กลางในการรับข้อมูลคำขอยืมครุภัณฑ์หรือเบิกวัสดุสิ้นเปลือง และภาพหลักฐานส่งคืนครุภัณฑ์จากผู้ใช้งาน พร้อมทำหน้าที่ส่งข้อมูลรายงานสถิติและใบคำขอส่งถึงแอดมิน เพื่อพิจารณาอนุมัติหรือปฏิเสธคำขอ ตลอดจนทำหน้าที่ส่งคำขอส่งอีเมลไปยัง SMTP Server เพื่อดำเนินการส่งจดหมายแจ้งเตือนสถานะอนุมัติ/ปฏิเสธ หรือส่งอีเมลเตือนส่งคืนครุภัณฑ์เกินกำหนดด่วนพิเศษไปยังผู้ใช้งานโดยตรง

3. แผนภาพขั้นตอนการทำงานของระบบ (System Flowchart)

แผนภาพแสดงขั้นตอนการทำงาน ลำดับความคิด และทิศทางข้อมูลของระบบทั้งหมด ตั้งแต่การตรวจสอบสิทธิ์การเข้าใช้งาน การกดยื่นคำขอของนักศึกษา/อาจารย์ และขั้นตอนการพิจารณาตรวจสอบการยืม-คืนของแอดมิน

รูปที่ 3-1: แผนภาพขั้นตอนการทำงานของระบบ (System Flowchart)

คำอธิบายรายละเอียดแผนภาพจากรูปที่ 3-1: แสดงขั้นตอนการทำงานเริ่มต้นจากการเข้าสู่ระบบ (Login) โดยระบุรหัสประจำตัว จากนั้นระบบจะทำการตรวจสอบสิทธิ์การเข้าใช้งาน (Check Role) เพื่อแยกการประมวลผลออกเป็น 2 สิทธิ์ หากเข้าใช้งานในสิทธิ์ผู้ใช้ทั่วไป (นักศึกษา/อาจารย์) จะเข้าสู่การค้นหาและตรวจสอบครุภัณฑ์คงเหลือในคลัง แล้วกดยื่นเรื่องขอยืมครุภัณฑ์ (Durable) หรือขอกดเบิกวัสดุสิ้นเปลือง (Consumable) เพื่อส่งเรื่องให้แอดมินพิจารณาคำขอ หากระบบแจ้งผลปฏิเสธจะทำการส่งอีเมลและสิ้นสุดการทำงานทันที หากได้รับการอนุมัติ ผู้ยืมจะรับอุปกรณ์ไปใช้งาน และเมื่อต้องการส่งคืน ผู้ใช้จะต้องกดยื่นเรื่องส่งคืนพร้อมส่งภาพถ่ายหลักฐานสภาพการคืน เมื่อแอดมินกดยืนยันรับของเข้าคลังจึงจะเสร็จสิ้นการทำงาน ในทางกลับกัน หากเป็นสิทธิ์ผู้ดูแลระบบ (Admin) จะสามารถจัดการหน้าแดชบอร์ด จัดการคลังอุปกรณ์/สถานที่ และตรวจสอบรายการค้างส่งคืนเพื่อส่งจดหมายแจ้งเตือนเร่งคืนครุภัณฑ์โดยตรงครับ

4. แผนภาพความสัมพันธ์ของข้อมูล (ER Diagram)

แผนภาพแสดงสถาปัตยกรรมความสัมพันธ์ของฐานข้อมูลเชิงสัมพันธ์แบบ One-to-Many (1:N) ระหว่างข้อมูลผู้ใช้ ข้อมูลครุภัณฑ์และวัสดุ ข้อมูลใบคำร้องยืมคืน ข้อมูลประวัติการซ่อมแซม และข้อมูลแผนผังห้องปฏิบัติการ

รูปที่ 3-3: แผนภาพแสดงความสัมพันธ์ของข้อมูล (ER Diagram)

คำอธิบายรายละเอียดแผนภาพจากรูปที่ 3-3: แสดงความสัมพันธ์ระหว่างเอนทิตี (Entities) ต่างๆ ในฐานข้อมูลของระบบจัดการยืม-คืนครุภัณฑ์ ตัวอย่างเช่น:
1. **ความสัมพันธ์ระหว่างเอนทิตี User และ BorrowRequest** ผ่านความสัมพันธ์ 'ยื่นคำขอ' โดยเป็นความสัมพันธ์รูปแบบหนึ่งต่อกลุ่ม (One-to-Many หรือ 1:N) ซึ่งอธิบายได้ว่า ผู้ใช้งาน 1 คน สามารถส่งเรื่องขอยืม-คืนครุภัณฑ์ได้หลายรายการ ทั้งนี้ เอนทิตี User ประกอบด้วยคุณลักษณะ id (คีย์หลัก), username, full_name, email และ role ในขณะที่เอนทิตี BorrowRequest ประกอบด้วย id (คีย์หลัก), status และมี user_id เป็นคีย์นอก (Foreign Key)
2. **ความสัมพันธ์ระหว่างเอนทิตี Equipment และ BorrowRequest** ผ่านความสัมพันธ์ 'ถูกยืม' โดยเป็นความสัมพันธ์รูปแบบหนึ่งต่อกลุ่ม (One-to-Many หรือ 1:N) ซึ่งอธิบายได้ว่า อุปกรณ์ครุภัณฑ์ 1 ชิ้น สามารถมีประวัติการถูกยืมในคำขอต่าง ๆ ได้หลายรายการ ทั้งนี้ เอนทิตี Equipment ประกอบด้วยคุณลักษณะ id (คีย์หลัก), equipment_code, name และ status ในขณะที่เอนทิตี BorrowRequest มี equipment_id เป็นคีย์นอก (Foreign Key)
3. **ความสัมพันธ์ระหว่างเอนทิตี Room และ Equipment** ผ่านความสัมพันธ์ 'เก็บรักษา' โดยเป็นความสัมพันธ์รูปแบบหนึ่งต่อกลุ่ม (One-to-Many หรือ 1:N) ซึ่งอธิบายได้ว่า ห้องปฏิบัติการคอมพิวเตอร์ 1 ห้อง สามารถใช้จัดเก็บครุภัณฑ์ได้หลายชิ้น ทั้งนี้ เอนทิตี Room ประกอบด้วยคุณลักษณะ id (คีย์หลัก) และ name ในขณะที่เอนทิตี Equipment มี room_id เป็นคีย์นอก (Foreign Key)
นอกจากนี้ ยังมีตารางแผนผังสถานที่ ได้แก่ Building สังกัด Floor และ Floor สังกัด Room รวมถึงการยื่นคำร้องซ่อมบำรุงผ่านตาราง RepairRequest จากผู้ใช้ (User) ไปยังอุปกรณ์ชิ้นนั้นๆ (Equipment) ซึ่งล้วนแต่เชื่อมโยงกันในรูปแบบความสัมพันธ์แบบหนึ่งต่อกลุ่ม (1:N) เพื่อจัดเก็บโครงสร้างความสัมพันธ์เชิงสัมพันธ์ของระบบอย่างเป็นระเบียบ

5. สถาปัตยกรรมระบบ (System Architecture - 3-Tier)

แผนภาพแสดงสถาปัตยกรรมโครงสร้างการพัฒนาระบบยืม-คืนครุภัณฑ์ โดยแบ่งเป็น 3 ชั้น (3-Tier Architecture) ได้แก่ Presentation Layer (ส่วนติดต่อผู้ใช้), Application Layer (เซิร์ฟเวอร์ประมวลผล Python/Flask โฮสต์บน Vercel), และ Data Layer (ส่วนจัดเก็บข้อมูลระบบ Supabase PostgreSQL)

รูปที่ 3-5: แผนภาพแสดงสถาปัตยกรรมระบบจัดการยืม-คืนครุภัณฑ์ (System Architecture)

คำอธิบายรายละเอียดแผนภาพจากรูปที่ 3-5: แสดงแผนภาพสถาปัตยกรรมระบบจัดการยืม-คืนครุภัณฑ์ห้องปฏิบัติการคอมพิวเตอร์แบบ 3 ระดับ (3-Tier Architecture) ที่ประกอบด้วยส่วนแสดงผลหน้าจอ (Presentation Layer) บนอุปกรณ์ที่หลากหลายทั้งคอมพิวเตอร์ แท็บเล็ต และสมาร์ทโฟน ผ่านเทคโนโลยี HTML5, CSS3, JavaScript, ส่วนประมวลผลคำสั่งระบบ (Application Layer) ผ่านเว็บเซิร์ฟเวอร์ด้วยภาษา Python และ Flask Framework โฮสต์บนคลาวด์ Vercel, และส่วนจัดการฐานข้อมูล (Data Layer) ด้วยระบบ PostgreSQL บนบริการ Supabase โดยทั้งสามส่วนทำงานประสานกันและรับส่งข้อมูลผ่านโปรโตคอล HTTPS และคำสั่ง SQL Query อย่างเป็นระบบเพื่อรองรับการทำงานทั้งหมดของโครงการ

6. การออกแบบต้นแบบหน้าจอหลัก (User Dashboard UI Prototype)

การออกแบบส่วนติดต่อผู้ใช้งานหลัก (User Interface) สำหรับหน้าแสดงรายการครุภัณฑ์และการจัดการสิทธิ์การขอยืม-คืนของผู้ใช้

รูปที่ 3-4: แผนภาพแสดงการออกแบบต้นแบบหน้าจอหลัก (User Dashboard / Equipment List)

คำอธิบายรายละเอียดจากรูปที่ 3-4: การออกแบบต้นแบบหน้าจอหลัก (User Dashboard) ประกอบด้วย 3 ส่วนหลัก ได้แก่ (1) แถบนำทางด้านข้างและด้านบน (Sidebar & Navbar) สำหรับเปลี่ยนสิทธิ์ สลับการทำรายการ และปุ่มเปลี่ยนโหมดกลางวัน/กลางคืน (2) ส่วนแถบค้นหาอัจฉริยะและตัวกรองอุปกรณ์ (Search & Filter Area) สำหรับพิมพ์ค้นหาชื่อรหัสอุปกรณ์ที่มีการหน่วงระบบ Debounce และปุ่มตัวกรองตามหมวดหมู่ ตึก ชั้น หรือห้องปฏิบัติการ และ (3) รายการแสดงการ์ดรายละเอียดครุภัณฑ์และวัสดุทั้งหมด (Equipment Grid Catalog) พร้อมแสดงรูปภาพ รหัสครุภัณฑ์ สถานะสต็อกคงเหลือ และปุ่มสีน้ำเงินสำหรับส่งคำขอยืมครุภัณฑ์หรือปุ่มขอเบิกวัสดุสิ้นเปลือง

TC-07 อนุมัติคำขอ (Approve) แอดมินกดอนุมัติคำขอยืมครุภัณฑ์ (Positive) กดปุ่มอนุมัติ (เช็คผ่าน POST) สถานะใบยืมเปลี่ยนเป็น 'อนุมัติแล้ว' (Approved), สต็อกอุปกรณ์ที่พร้อมให้ยืมลดลง 1 เครื่อง, ส่งอีเมลอนุมัติไปยังผู้ยืมทันที สถานะเปลี่ยน สต็อกคงเหลือลดลง และส่งเมลแจ้งอนุมัติสำเร็จ PASS
TC-08 ส่งคืนครุภัณฑ์ (Return) ผู้ใช้กดคืนครุภัณฑ์โดยแนบไฟล์รูปถ่ายหลักฐานถูกต้อง (Positive) ไฟล์ภาพ: receipt.png (อัปโหลดหลักฐานส่งคืน) สถานะเปลี่ยนเป็น 'รอรับคืน' (Return pending), ชื่อไฟล์ภาพถูกจัดเก็บลงฐานข้อมูล, นำภาพไปแสดงในหน้าแอดมิน ระบบรับไฟล์รูป บันทึกลง Supabase และขึ้นแจ้งเตือนรอรับคืนฝั่งแอดมิน PASS
TC-09 ส่งคืนครุภัณฑ์ (Return) ผู้ใช้กดส่งคืนโดยไม่เลือกอัปโหลดรูปภาพหลักฐาน (Negative) ไฟล์ภาพ: [ว่าง] ระบบล็อกไม่ยอมให้ส่งคืน พร้อมแสดงข้อความเตือนให้แนบรูปภาพก่อน แสดงคำเตือนสีส้มระบุว่าจำเป็นต้องแนบไฟล์รูปหลักฐาน PASS
TC-10 รับคืนเข้าคลัง (Confirm) แอดมินตรวจสอบรูปหลักฐานและกดยืนยันรับของคืนเข้าคลัง (Positive) กดปุ่มรับของคืน (เช็คผ่าน POST) สถานะใบยืมเป็น 'คืนเรียบร้อย' (Returned), บันทึกเวลาคืนจริง, สต็อกครุภัณฑ์บวกกลับคืนคลัง 1 ชิ้น สถานะเปลี่ยน สต็อกเพิ่มกลับคืนคลัง และบันทึกเวลาส่งคืนสำเร็จ PASS
TC-11 ค้นหาครุภัณฑ์ (Search) พิมพ์คำค้นหาชื่ออุปกรณ์ที่ต้องการค้นหา (Positive) คำค้นหา: "กล้อง" ตัวกรองจาวาสคริปต์กรองการ์ดให้แสดงเฉพาะกล้อง โดยไม่มีความหน่วงขณะพิมพ์ (พิมพ์ลื่นไหลด้วยระบบ Debounce 150ms) หน้าจอกรองแสดงเฉพาะกล้องอย่างรวดเร็วและ Snappy ไม่หน่วงคอมพิวเตอร์ PASS
TC-12 ค้นหาครุภัณฑ์ (Search) พิมพ์ชื่ออุปกรณ์ที่ไม่มีอยู่ในระบบคลัง (Negative) คำค้นหา: "ตู้เย็น" หน้าจอซ่อนการ์ดครุภัณฑ์ทั้งหมด และไม่แสดงรายการใดๆ การ์ดอุปกรณ์ทุกใบถูกซ่อนและไม่มีรายการแสดงผล PASS
